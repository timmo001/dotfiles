[OpenCode](https://opencode.ai) is the main interactive agent UI on my machines: sessions, slash commands, plugins, and [Herdr](https://herdr.dev) panes. A cloud session runs [Claude Code](/claude/overview/) instead, but this repo still publishes the config, from `agents/.config/opencode/`.

## Layout

| Piece | Why |
| --- | --- |
| `agents/.config/opencode/` | Agents, commands, `plugins/`, and shared `lib/` |
| Shared [skills](/agents/skills/) | Skills repo `main` + repo-local skills (see Skills page) |
| Private overlay | Machine-specific OpenCode packages, AGENTS source, and MCP wiring |

## Layers

| Layer | Role |
| --- | --- |
| Agents | Execution posture (permissions, tools, plan mode, delegation) |
| Commands | Thin routers: intent, arguments, required skills/context, output shape |
| Skills | Reusable workflows and behavioural contracts ([Skills](/agents/skills/)) |
| Plugins | Context injection and enforcement hooks (commit context, guards, workflows) |

Commands do not own long workflows; skills and plugins do. AGENTS stays to cross-cutting policy that no skill description already carries.

## Sync and publish

| Command / flow | Purpose |
| --- | --- |
| `dot agent sync` | Mirror global AGENTS into other harness instruction files (Cursor, Claude) |
| `dot mcp sync` | Regenerate MCP configs from private `mcp.yml`; OpenCode repos opt in via `opencode_mcp` in private `dot-git.yml` |
| `dot skills` | Check and apply skill updates from the skills repo |
| `dot update` / `dot init` | Run agents-sync (and related refresh) as part of maintenance |

## Runtime

Sessions often run inside Herdr panes (OpenCode integration checked by `dot doctor`). The public Zsh config aliases `opencode` to OpenCode 2 (`opencode2`). See [Agents](/agents/overview/) for how the harnesses fit together.

The `distro/cloud` branch is the [Ubuntu server](https://ubuntu-server.dotfiles.timmo.dev/) build with a layer for cloud agent environments, starting with [Claude Code cloud sessions](https://code.claude.com/docs/en/claude-code-on-the-web). A session runs in a short-lived VM, so this branch doesn't stow packages or start services. It gives the session `dot`, the pinned toolchain and my Claude Code setup.

```bash
# The cloud environment's setup script
curl -fsSL https://raw.githubusercontent.com/timmo001/dotfiles/distro/cloud/cloud/setup.sh | bash
```

| Piece | Why |
| --- | --- |
| `cloud/setup.sh` | Clones this branch, installs [mise](https://mise.jdx.dev/) and the toolchain, builds `dot` and runs `dot cloud setup`. [Environment caching](https://code.claude.com/docs/en/cloud-environments#environment-caching) snapshots the result, so later sessions skip it |
| `dot cloud setup` | Links the cloud Claude Code settings, writes the user `CLAUDE.md` and links the shared skills into `~/.claude/skills` |
| `cloud/claude/settings.json` | User settings for a cloud session, without the desktop hooks that need stowed config |
| `cloud/claude/CLAUDE.md` | Notes on what a cloud VM has and lacks, placed ahead of my global agent instructions when the private overlay is reachable |

| Left out | Why |
| --- | --- |
| Stow packages and shell config | Nobody uses a shell in the VM directly |
| User services, Herdr and the dashboard | Nothing runs between sessions |
| The private overlay's machine config | Only its global agent instructions are used |

## Keeping up

The branch rebases onto `distro/ubuntu-server`. The Cloud rebase workflow force-pushes a clean rebase and opens an issue when it can't, and the `cloud-rebase` skill finishes it. [Changes from the desktop](/server/changes/) lists everything this branch and the server change.

:::caution[Personal setup]
This build is tuned for my own cloud environment and a private overlay that is not public. Borrow the pieces you want rather than pointing your setup script at it.
:::

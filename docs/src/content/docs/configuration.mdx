---
title: Configuration
description: What the public branch and the private overlay each provide in a cloud session.
---

Behaviour prefers CLI flags. Environment variables cover process context and secrets. Private data stays in `~/.config/dotfiles-private`, which a session clones or links once it can reach it.

| Piece | Why |
| --- | --- |
| `cloud/` | The setup script and the Claude Code settings and notes; see [Claude Code](/claude/overview/) |
| `.dot-skills.yml` | Shared skills not linked in a session (only `pkexec-root`) |
| `.dot-private.yml` | Which parts of the private overlay apply; this build drops the server's repository filter so every tracked repository can be looked up |
| Private overlay | Global agent instructions and `dot-git.yml` |

| Private file | Role in a session |
| --- | --- |
| `agents/.config/opencode/AGENTS.md` | Global agent instructions, added to `~/.claude/CLAUDE.md` |
| `dot-git.yml` | Tracked repositories for `dot repo`, plus PR and issue tracking settings |

Their paths follow my machines' layout, so a repository attached to a session is under `/home/user` instead, and the rest aren't cloned. Flags and env details live in `dot --help` and code.
